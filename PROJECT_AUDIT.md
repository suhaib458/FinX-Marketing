# FinX Marketing Platform — Technical Audit

## Executive summary

The uploaded project is a strong product prototype with a polished React UI and a partially implemented production backend. It is not yet a fully connected production application: authentication is real Firebase authentication, while several core product flows still use browser-local mock services.

## Current architecture

- Frontend: React 19, Vite 8, React Router 7, CSS design system, Arabic/English RTL/LTR support.
- Authentication: Firebase Authentication (Google + email/password + verification/reset flows).
- Backend: Node.js + Express 5.
- Database: Prisma 7 with MySQL/MariaDB.
- Storage: Firebase Storage through Firebase Admin.
- Security middleware: Helmet, CORS allow-list, rate limiting, Zod validation, request IDs/logging.
- Testing: Vitest suites exist for frontend and backend, including auth/security/assets.

## Authentication failure observed in the supplied walkthrough video

The Google flow successfully reaches account selection. The failure happens after Firebase authentication when the frontend synchronizes the Firebase identity with the FinX backend.

Root cause in the uploaded configuration:

- `src/services/authApi.js` defaulted to `http://localhost:3001/api/v1`.
- The uploaded `.env.local` had Firebase keys but did not define `VITE_API_BASE_URL`.
- If only the Vite frontend is running, or if the frontend is deployed without a reachable backend at that address, `/auth/session` cannot be reached and the UI reports a network error.

The same backend dependency affects email/password login, which explains why both methods appear broken.

## Security observations

Positive:

- `.env`, `.env.*`, Firebase Admin JSON files, service-account files and private-key formats are ignored by Git.
- The local Git history inspected did not contain the local `.env.local`, backend `.env`, or `firebase-admin.json` paths.
- Backend applies Helmet, CORS, rate limiting and schema validation.
- Gemini API keys are designed to remain server-side and are never exposed through `VITE_*` variables.

Important operational note:

- The uploaded archive contains live local credential/config files. They are excluded from GitHub by `.gitignore`. If this archive or those credentials were ever shared publicly elsewhere, rotate the affected credentials.
